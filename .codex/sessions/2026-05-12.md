## Session 2026-05-12

### What Was Built

A complete Codex hook system for Claude Code that automatically generates explanations and session summaries. The system persists API keys system-wide, handles Windows path and encoding issues, and includes a retroactive backfill tool (`retro.py`) for documenting existing projects.

Shifted the prompt philosophy from pure documentation to pedagogy—explanations now teach system-level reasoning rather than just describing what code does.

### Key Decisions

**Pedagogy over documentation.** Early commits generated straightforward code explanations. Later refactors reframed Codex as a teaching tool: every explanation must cover the operational reality that forced the code into existence, what it protects against, and what invariants it maintains. This required reworking `codex_post_tool_use.py` and `codex_stop.py` prompts twice.

**Platform-aware API key handling.** Rather than assume environment variables, the installer now prompts for the API key during setup and persists it at the OS level (Windows registry vs. shell rc files). This was broadened after initial Windows failures.

**Pre-tool-use hook added late.** A `codex_pre_tool_use.py` hook was introduced at the end to inject prior `.codex` context before edits—allowing Claude to reference previous explanations when making changes.

### Lessons and Gotchas

**UTF-8 encoding crashes on Windows.** Early sessions crashed with cp1252 errors when writing to stdout on Windows. Fixed by reconfiguring stdout explicitly to UTF-8 before any output. This bit multiple files and required explicit `encoding='utf-8'` on all `settings.json` file opens.

**Path expansion fragile.** Windows path handling required fixes early (commit 2). Relatedly, making source root configurable via `.codex/config.json` (commit 3) was necessary because projects vary in structure.

**Retroactive backfill is non-trivial.** The retro.py tool had to be rewritten substantially—initial 335-line version was bloated; condensed to 158 lines after understanding the actual requirements.

**Hook system assumes git diff.** The entire premise depends on extracting what changed from git. If git isn't initialised, hooks fail silently. This isn't documented as a hard requirement in INSTALL.md but should be.
