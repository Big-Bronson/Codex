## Session 2026-05-13

### What Was Built
- Created a `.gitignore` file to exclude self-generated Codex and Claude analysis output (`.codex/`, `.claude/`) and Python bytecode artifacts from version control.
- Backfilled the `.codex/` directory with complete documentation and configuration for the Codex hook system, including README, install guide, Claude conventions, hook definitions, and retroactive session records.
- Added an `install.py` script to automate the setup of Codex hooks in new projects.

### Key Decisions
The session established that Codex output should never be committed to git. This prevents repository bloat from self-referential analysis and avoids merge conflicts when multiple developers run the tools locally. The decision to document the system retroactively (via `.codex/retro.md`) means previous work can be recovered and explained even if it wasn't captured in real-time. The hook system is designed to fire automatically during Claude sessions—PostToolUse generates file explanations, Stop generates session summaries—so developers don't manually request documentation.

### Lessons and Gotchas
The system is designed to be self-documenting: every file that gets modified triggers automatic explanation generation, and every session generates a summary. This means the `.codex/` directory itself becomes voluminous but serves as a complete audit trail. The retroactive backfill indicates this session was partly about documenting decisions made in a previous session (2026-05-12), suggesting the hook system may not have been fully capturing context in real-time initially. Projects can override global Codex behavior with a local `CLAUDE.md`, allowing per-project teaching conventions.
