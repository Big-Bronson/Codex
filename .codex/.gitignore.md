## .gitignore

### What This File Does
This file tells Git which files and directories to exclude from version control. When you run `git add`, `git commit`, or other Git operations, any paths matching patterns in .gitignore are automatically skipped, preventing them from being tracked in the repository history.

### Why It Exists
The repository runs automated tools (Codex hooks) that generate temporary output files during development and testing. These generated artifacts don't belong in version control because they're ephemeral, reproducible, and would create noise in commit history. This file establishes a clear boundary between source code (which belongs in Git) and build/cache artifacts (which don't).

### What It Protects Against
Without this file, developers would accidentally commit generated Python bytecode files (`.pyc`), pycache directories from multiple Python runs, and Claude AI tool outputs that are meant to be transient. This would pollute the repository with files that vary across machines and runs, creating merge conflicts and obscuring meaningful code changes in the Git log.

### Invariants
- Patterns must remain valid glob syntax that Git recognizes
- The file must exist at the repository root to apply globally
- Patterns should exclude only artifacts, not source code needed for the project to function

### Key Patterns
**Glob pattern matching**: Uses simple wildcards like `*.pyc` (all Python compiled files) and directory names like `__pycache__/` (Python's standard cache directory). These are standard .gitignore conventions that developers expect.
