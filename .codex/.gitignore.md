## .gitignore

### What This File Does
This file tells Git which files and directories to exclude from version control. When you commit code, Git will ignore anything matching these patterns, preventing them from being tracked or pushed to the repository.

### Why It Exists
The repository runs Codex hooks and Claude analysis tools against itself, which generate temporary output directories (.codex/ and .claude/). These are self-referential artifacts that shouldn't pollute the git history. Similarly, Python's bytecode cache (__pycache__/ and *.pyc) is a build artifact that varies by environment and has no value in source control. This file prevents these temporary outputs from accidentally being committed.

### What It Protects Against
It prevents three failure modes: (1) accidental commits of self-generated analysis output that would create confusing diffs and bloat the repository; (2) merge conflicts when different developers run the tools locally and generate different cached output; (3) Python bytecode files that differ based on Python version and optimization settings, causing spurious changes.

### Invariants
- Every line matching a pattern must represent files or directories that should never be committed to this repository.
- The patterns must be broad enough to catch generated outputs across different execution contexts, but not so broad that they accidentally exclude source code.
- Any developer running Codex hooks or Python tools locally must have Git ignore their outputs automatically.

### Key Patterns
**Directory exclusion** — `.codex/` and `.claude/` explicitly exclude entire directories and their contents with trailing slashes. **Wildcard matching** — `*.pyc` uses glob patterns to match all Python compiled files regardless of location. **Comments** — the file uses `#` to document why each exclusion exists, aiding future maintainers.
